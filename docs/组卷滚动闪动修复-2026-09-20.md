# 组卷选题流「滚动闪动」修复（2026-09-20）

## 现象

组卷工作台的题目流（「全库试题 / 已选试题」那个长列表）向下滚动时画面疯狂闪动。
用户确认形态是**内容上下跳动**（题卡位置被推来推去），不是图片白闪、也不只是滚动条伸缩。

## 根因：滚动帧里的跨帧反馈闭环

`static/js/paper.js` 的虚拟滚动原先在**每一帧滚动**里做三件事，而这三件事互相触发：

| # | 代码 | 后果 |
|---|---|---|
| ① | `updatePaperVirtualList()` 无条件 `viewport.innerHTML = html` | 哪怕一张卡都没进出视口，也把视口内全部卡片重新生成一遍：KaTeX 重跑、`adaptChoicesGridLayout` 每卡再强制 reflow 几次、题图 `<img loading="lazy">`（`:4271`）回落到未加载状态 |
| ② | 实测回填写 `heights`，`spacer.style.height` 随之改变 | 滚动条长度在滚动时忽长忽短；估计值 `PAPER_ITEM_ESTIMATE = 264` 与实测值差多少，每轮推的幅度就有多大 |
| ③ | `container.scrollTop = container.scrollTop + delta` | **改 scrollTop 会再派发一次 scroll 事件** → 又排一帧 → 又重建又测量 |

③ 是闭合的那一环。`PAPER_MEASURE_PASSES = 4` 只限制**同一次调用内**的递归深度，
对这条**跨帧**的环毫无作用 —— 所以表现为滚动时持续跳，而不是跳一下就好。

次要来源：`ResizeObserver` 观察的正是每帧被 `innerHTML` 重写的那个 `viewport`。
高度一旦在「图片未加载 / 已加载」两值间振荡，观察者就永远触发下去。

## 修复（`static/js/paper.js`，替换原 `updatePaperVirtualList` 一带）

1. **窗口没变 → 一个 DOM 操作都不做。** 每帧先算 `start/end`，与 `lastStart/lastEnd`
   相同就只同步 `translateY` 然后返回。这是命中用户主诉的那一刀。
2. **窗口变了 → 只增删差异卡片。** 新增 `createPaperStreamCardEl` / `syncPaperVirtualWindow`：
   按 `q.id` 复用已渲染的卡（`rendered` Map），只 `appendChild` 新进视口的、只 `remove`
   滚出视口的。已加载的题图与已渲染的 KaTeX 不再被丢掉重来。
   元素位置由「按 `i` 递增追加」自然保证；下标写进了「上移/下移」的 onclick，
   所以 `dataset.vindex` 不一致的那张仍重建。
3. **程序改 scrollTop 一律登记。** `anchorPaperVirtualScroll` 写 `paperVirtual.selfScrollTop`
   记下期望值，scroll handler 见到 `scrollTop` 仍等于它就直接返回，不再排下一帧。
4. **重测不重建。** `ResizeObserver` 回调改为 `remeasurePaperVirtualWindow()`：只重量已渲染
   卡片的高度、必要时修正一次，**绝不重建** —— 一重建题图就回落，观察者会永远震荡。
5. **常量清理。** `PAPER_MEASURE_PASSES` 随递归一起删除（跨帧环不再需要它兜底）。
6. `container.innerHTML` 重设的地方（正常路径 + 空结果分支）调 `resetPaperVirtualWindow()`
   作废窗口缓存；否则下次同步会把游离的旧元素重新 `append` 回来。

新增只读观测点（供夹具断言，不改行为）：`PaperVirtualMath.stats()` / `resetStats()` /
`renderedIds()` / `lastWindow()` / `pendingSelfScroll()`。

| 受影响面回归子集 | **159 passed** |

关键断言（旧实现必然失败）：

- 窗口未变的那几帧：卡片元素引用**逐个不变**（证明不是「重建后内容恰好相同」）
- 窗口未变时 `domSyncs === 0`
- 一次窗口变化只做**一次** DOM 同步，且复用了已在视口内的卡片
- 连续滚动 31 帧，`domSyncs <= frames / 2`（旧实现是 `=== frames`）
- 程序派发的 scroll 被识别，不再触发新一轮更新
- 源码回归护栏：代码行里不再有 `viewport.innerHTML =`

## 两处夹具升级（假 DOM 必须跟上实现）

两个前端夹具的假 DOM 原先 `appendChild: function () {}` 是空操作，`children` 只由
`innerHTML` setter 生成。窗口同步改用真实树操作后，夹具看不见任何卡片，直接
`Cannot convert undefined or null to object`。

升级内容（两个夹具各自独立，不共享代码）：

- 真实维护 `children` / `parentNode`：`appendChild` / `insertBefore` / `removeChild` / `remove`
- `firstElementChild` / `nextElementSibling` getter
- `innerHTML` 改成 getter/setter：**有子元素时按子元素序列化回来**（否则「渲染出了什么」
  在夹具里看不见），setter 按顶层 `data-vcard` 切分生成子卡
- 模拟浏览器行为：`container.innerHTML` 重建会连旧的 `spacer` / `viewport` 一起丢掉，
  新 viewport 是空的 —— 不做这一步，窗口同步会以为上一批卡片还在
- `paper_multisubject_check.js` 的 `elementFor` / `createElement` 各自绑定本沙箱的元素表
  （它一次 boot 多个沙箱，模块级单例会串台）

## 遗留

- `tools/paper_smoothness_test.js` 早已失效：仍引用 2026-09-19 重写前的固定 stride 常量
  （`PAPER_ITEM_HEIGHT` / `PAPER_STRIDE`），且 `ROOT` 未定义，一跑就抛。它测的指标
  （DOM 节点数恒定、KaTeX 只渲染可视区）已由上面两个夹具覆盖，建议直接删除或重写。
- 真实 Safari 下的最终观感需用户刷新页面确认（`static/**` 改动即时生效，无需重启服务）。
