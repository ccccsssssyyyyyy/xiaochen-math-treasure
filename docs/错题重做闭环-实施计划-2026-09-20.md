# 错题重做闭环 · 实施计划（2026-09-20）

## 0. 一句话

给错题工作台加一条闭环：**错题 → 生成重做卷 → 导出给学生做 → 手动录入二遍结果 → 自适应安排下次重做 → 掌握归档**；题库记录每道题错了几遍、是否掌握。

## 1. 已锁定的设计决策

1. **录入页放错题工作台**（它本身就是记学生掌握情况的地方），新增子标签「重做复习」。
2. **结果回录 = 手动逐题勾选 对/错**（不做扫描自动判分，避免解答题误判）。
3. **重做间隔 = 自适应（类遗忘曲线）**，受硬约束：学生只有周末能打印带走 → **所有非周末的建议重做日顺延到下一个周六**。
4. **掌握判定**：同一题**不同日期**连续做对 2 次 = `mastered`；同日内连做不算。保留人工手动覆盖。
5. **防假性掌握（按重做遍数变换选择题）**：第 1 遍原顺序；第 2 遍打乱选项（答案键同步重映射）；第 3 遍起不提供选项。**仅在导出时变换，库内原题保持规范顺序**。
6. 为支撑打乱/不选项，`questions` 增加结构化 `correct_answer`（正确字母）。
7. **前端最终样式必须与现有工作台 UI 一致**：复用 `app.css` 现有 class 与配色，沿用三工作台切换、`html.init-ws-*` 防闪烁规则，不引入新视觉语言。

## 2. 数据模型改动（迁移 v1011）

### 2.1 `questions` 新增列（只加列、不回填）

| 列 | 类型 | 语义 |
|---|---|---|
| `correct_answer` | VARCHAR(10) DEFAULT '' | 选择题正确字母（多选存如 `AC`）；打乱后重映射答案键的依据 |
| `wrong_count` | INTEGER DEFAULT 0 | 这道题累计做错次数（首次错题 + 每次重做判错） |
| `redo_count` | INTEGER DEFAULT 0 | 累计重做次数（被排进重做卷的次数） |
| `redo_correct_streak` | INTEGER DEFAULT 0 | 连续做对次数（判错归零；跨日才算） |
| `mastery_status` | VARCHAR(20) DEFAULT 'pending' | pending / redone / mastered |
| `next_redo_due` | DATE NULL | 建议重做日（顺延到周末后） |
| `last_redo_at` | DATETIME NULL | 最近一次重做录入时间 |

### 2.2 新表 `redo_attempts`（每次重做一行）

`id / student_id / paper_id / question_id / attempt_no / result(correct|incorrect) / option_mode(plain|shuffled|no_option) / attempted_at / created_at`

索引：`question_id`、`paper_id`、`(student_id, result)`。

### 2.3 `papers.metadata_json` 新增键（零迁移，沿用混科先例）

`is_redo=true`、`redo_scope={student_id, source:"mistake"}`、每题的 `attempt_no` 快照（导出时据此决定选项变换）。

### 2.4 迁移实现

`mathbank/db_migrations.py` 新增 `_add_redo_tables_and_question_columns_v1011`：建表走 `Base.metadata.create_all`，加列走 `ALTER TABLE`，符合既有 v1005/v1008 模式，**幂等可重跑**；`LATEST_SCHEMA_VERSION` 升到 `1011`，在 `migrate_database` 加 `current == 1010` 分支。

**掌握度计算（后端唯一口径，抽成纯函数便于单测）**：

- 判错 → `wrong_count+1`、`redo_correct_streak=0`、`mastery='pending'`、`next_redo_due=` 最近周末。
- 判对 → `redo_correct_streak+1`；若同题上次做对日期 ≠ 今日且 `streak>=2` → `mastery='mastered'`、`next_redo_due=NULL`；否则 `mastery='redone'`、`next_redo_due=` 今天 + 步进（顺延周末）。
- 步进：首次错 / 判错 → 最近周末；连对 1 次 → +14 天顺延周末；封顶 30 天。

## 4. 导出管线（选项变换）

- 在 `build_latex_document` 之前，按每题 `attempt_no` 变换 `content`：
  - `attempt_no<=1`：原样；
  - `==2` 且单选/多选：解析 `\begin{choices}...\item...\end{choices}` 序列 → 打乱 → 重排字母 → 用 `correct_answer` 重映射答案键；
  - `>=3` 且选择题：剥离 choices 环境，只留题干；
  - 填空/解答题：原样。
- 变换函数放新模块 `mathbank/choice_transform.py`（纯函数、可单测），复用 `latex_normalize.py` 的解析能力。
- **库内原题不写回**。

## 7. 风险与未决

- `correct_answer` 依赖导入/OCR 阶段可靠落库；**存量题无值 → 打乱/不选项对该题降级为「原样」**，不阻塞。
- 多选题「不提供选项」档的判分口径（是否允许部分对）——暂按全对才 `correct`，待定。
- 重做卷与普通卷共用 `papers` 表，列表/导出侧需区分，避免污染常规组卷列表。
- 与既有 `MistakeRecord.mastery_status`（手动）的关系：本题库 `questions.mastery_status` 为权威；错题记录侧改为按重做历史镜像回写。

### 8.2 掌握度不是累加，是**按历史重放**

计划写的是「判错 +1 / 判对 +streak」，实现时改成 `_replay_question_state(question, attempts)`：把 `redo_attempts` 全部按时间顺序重放一遍，得到 `wrong_count / mastery_status / next_redo_due`。

原因：老师会**改判**（同一份卷同一题从做错改成做对）。累加式实现无法撤销上一次判定，改判会留下幽灵错次。重放式的语义是「这一行是一次判定结果」，改判=覆盖，天然幂等。

推论（很重要，写测试时踩过）：**同一份卷里一道题只有一行 `redo_attempts`**，所以「同一天连做两遍」在结构上不可能攒出连对——跨日连对必须换一张新卷。

### 8.3 选项变换的两个硬点

1. **只在导出/录入视图变换，库内原题一个字节都不动**。变换由 `attempt_no` 驱动，放进 `mathbank/choice_transform.py`。
2. **打乱必须可复现**：`random.Random(paper_id * 1_000_003 + question_id)`，否则每次导出选项顺序不同，老师和学生对不上纸面。
3. **答案键重映射要能校验**：抽答案字母时校验「抽到的字母集合 == `correct_answer`」，不一致就**拒绝打乱、降级原序**。宁可原序，也不能把答案键指错。

### 8.4 真实题库的答案格式（覆盖率踩坑）

原正则只认「故选 / 答案为 / 正确答案 / 答案」开头的引导词式，实测覆盖率很低。真实库主要用另外两种：

- `【答案】ACD`
- **首行裸字母**：`ACD\r\n\r\n由…`

改成 `_answer_letter_span()` 三格式都认（首行裸字母优先，要求字母后接换行/结尾以免误吞题干）。实测 MCQ 783 道抽到 680 道（**86.8%**），未抽到的样本人工确认无误判冲突。抽不到的题自动降级原序，不阻塞出卷。

### 8.5 重做卷与组卷历史的关系

重做卷复用 `papers` 表，靠 `metadata_json.is_redo=true` 区分，**零迁移**。

`list_papers` 早期把重做卷整个过滤掉，看着干净，实则会把**认领进来的那张卷**（老师自己排的、
印给学生做过的那一份组卷）从历史里抹掉 —— 比多一行更费解。现在的口径是**原样列出 + 打标签**：
`is_redo`（重做卷）、`is_adopted_redo`（来自组卷台认领）、`graded_at`。前端据此显示
「重做卷 · 认领」标签与「录入结果」入口。重做卷仍**不计** `usage_count`。

### 8.6 前端

`static/js/redo.js`（IIFE + `window.*` 出口，无构建），挂载为错题工作台的一级子视图（与「扫描录入」并列的子标签）。视觉一律复用 `app.css` 的 `glass-*`，未引入新语言。

**录入按钮（做对/做错/上一题/下一题/导出/隐藏答案）是 `index.html` 里的静态按钮**，`redo.js` 只负责填卡片内容——写测试夹具时容易误以为按钮在动态卡片里。

### 8.9 人工标注掌握度：标注是**事件**，不是字段

老师需要能自己说「这道题她其实会了」。但直接写 `mastery_status='mastered'` 和现有的
「重放即真相」模型冲突：下次任何一次录入都会把它覆写掉，而老师根本不知道自己的标注什么时候失效。

做法是把标注当成**历史里的一条事件**：新增 `questions.mastery_override` / `mastery_override_at`
（v1012 迁移），重放时按时间戳与 `redo_attempts` 一起排序。于是三种情形都不用写特例：

| 情形 | 结果 |
|---|---|
| 标注之后**又做错** | 更晚的录入把状态推回 `pending`，重新进重做池 ← 这正是要的语义 |
| 补录一张**旧卷**（日期早于标注） | 排序在前，推翻不了标注 |
| 同一天既标注又录入 | 按**日期**排、同日标注在录入之后（即标注优先）。录入时间戳一律取当天 12:00，按分钟排会让「上午标、下午录」与「下午标、上午录」给出相反结果，老师无法预期 |

**硬约束：标注绝不能写进 `redo_attempts`。** 因为 `redo_count = len(attempts)`，而
`_redo_attempt_no = redo_count + 1` 决定导出时的选项变换档位（第 3 遍起剥选项）。
插一行会把每道被标注的题往后推一遍，第 3 遍的「无选项」档直接错位成第 4 遍 —— 而这是
**印在纸上的**，学生拿着卷子就发现不对。所以标注走独立两列。

被更晚的录入推翻时**就地清空标注列**，让「有标注」严格等于「标注正在生效」：否则一道已经
判回未掌握的题会挂着「人工标注」徽章，老师看不出到底哪个说了算。清空不改变任何计算结果
（`apply_mastery_override` 只动掌握度与排程两个键，而每次 `apply_attempt` 都会整键覆写）。

**取消标注的语义是「撤回我的话」，不是「把这题算成没过」**：清空两列后状态回落到纯历史重放
的结果（那遍重做判对 → `redone`，并重新排出建议重做日）。

顺带补的一个缺陷：取消标注（以及删掉最后一份重做卷）会让题目落到「**未掌握但没有建议重做日**」
——列表显示不出「建议 X」，按到期出卷也拿不准算不算它。重放末尾补上归一化：未掌握且从未重做过的
题，`next_redo_due` 置为最近的周六，与 `_seed_redo_pool` 的初始排程同口径。

用户已确认的两条口径：多选题**不允许部分对**（第 3 遍无选项档也按全对计，卡片上直接写明
「多选按全对计」）；人工标注入口**只放在重做复习面板的题卡上**（不放题库列表、不放批次列表）。

### 8.10 认领组卷台那张卷：第 1 遍练习的入口

**断点**：错题闭环的第 1 遍练习几乎必然发生在组卷台 —— 入库即送组卷、排版、印出来做掉。
可那条通道出的卷不带 `is_redo`，它的做题结果**没有任何入口**写回 `redo_attempts`。老师要记
效果，只能去重做台另生成一张：题序跟手上纸卷对不上，轮次还被少算一遍（`redo_round` 取
`max(attempt_no)`，而这遍根本没记账）。两条通道互不认识，闭环从第一环就断了。

补的是一座桥：**导出 PDF 之后问一句「要不要记作重做练习」**，把那卷认领进来。

| 环节 | 接口 | 关键点 |
|---|---|---|
| 值不值得问 | `POST /api/redo/eligibility` | **只回报数字，不落库**。`pooled_count=0`、已认领、已说过普通卷，三种都不问。PDF 是二进制响应塞不进元信息，所以另问一句 |
| 认领 | `POST /api/redo/adopt` | `{paper_id}` 认领已保存的卷；`{title, questions}` 是卷面还没落库（主编辑器导出时卷面还在试题篮里），先建卷再认领。幂等 |
| 别再问了 | `POST /api/redo/decline` | 「这就是普通卷」落库，同一张卷重印不再追问。**它只是闭嘴，不是禁止**：老师改主意显式认领照样成功，认领时把标记清掉 |
| 反悔 | `POST /api/redo/release` | 取消认领：撤录入记录 + 按剩余历史重算，卷回到组卷历史。`DELETE /api/redo/papers/{id}` 对认领卷等价于取消认领（不毁掉组卷历史那一条）；对错题台生成的重做卷仍是真的删除，两者用不同文案与图标区分 |

两条硬口径 ——

1. **呈现锁原序，记账不锁。** 纸卷早印出来、学生做完了，回头换题序等于换了一份卷子，所以
   认领卷 `redo_locked_order=true`，`_redo_transform` 一律按**第 1 遍**呈现。但
   `attempt_no` / `redo_count` / 连对判定仍按**真实历史**走 —— 若连记账也锁成第 1 遍，
   跨日连对会虚高、掌握判定提前，那是在造假。E2E 里同一道题、同一刻的两个对照：错题台出的
   卷是 `no_option`（历史第 3 遍），认领回来的纸卷是 `plain`，而它的 `attempt_no` 照样报 3。
2. **轮次只按池内题算**（`max(attempt_no)` over `wrong_count>0` 的那几道）。卷里混进的非错题
   不参与轮次，只在卡片上标「非错题 · 做错后进池」，但**照样能录** —— 做错了就进池。

认领写的全是 `metadata_json`（`is_redo` / `redo_locked_order` / `redo_adopted_from`），
**零迁移**，也不动 `usage_count`：这张卷本来就是老师真排出来、印过、发下去做过的组卷，
它只是多长出了「重做」这重身份（`_create_paper_from_payload` 刻意不走 `/api/paper/save`
的 `usage_count` 自增）。

未落库的卷面还带一个坑：主编辑器导出走试题篮、没有 `paper_id`。前端于是比对
`PaperStore.loadedPaperFingerprint` —— 载入 A 卷却改了题再导出，不能把结果记到 A 头上。

### 8.11 认领入口改到组卷面板第四格（2026-09-20 晚）

8.10 的认领问在「导出成功之后」，用户实测后否掉了：**弹窗打断导出，而且跳过去时视图还叠加**。
改成组卷面板导出行的第四格 —— 语义随之变化，从「卷的用途」变成**动作入口**：

| 操作 | 行为 |
|---|---|
| 点「PDF 预览」 | 只导出。不弹窗、不问、不认领 |
| 点「记作重做练习」 | 立即认领（`POST /api/redo/adopt`），第 4 格就地变绿为「已认领 · 第 N 轮」 |
| 点那个绿格 | 到错题台打开这张卷逐题录对错（`openRedoPaperFromLibrary`），**不跳页** |

三个实现要点：

1. **认领态必须挂 `PaperStore`，不能放 DOM。** 面板是 `window.renderPaperCanvas()` 整块
   重建 `innerHTML` 的（改分、换题、调留白都会触发），DOM 上的状态一重建就没了。
2. **认领态带卷面指纹。** 认领之后又改了题，`adopt.signature !== 当前指纹` → 面板显示回
   「未认领」。理由是纸卷与记录必须对得上：界面写着已认领、实际录进去的是另一份题序，
   比不显示更糟。
3. **认领成功后把 `loadedPaperId` / `loadedPaperFingerprint` 归位。** 否则第二次点击会再建
   一张重复卷（现场建卷那条分支不知道刚才已经建过了）。

下线的东西：`#redoAdoptPrompt` 浮层（index.html）、`maybePromptRedoAdopt` /
`confirmRedoAdopt` / `dismissRedoAdopt` / `state.adoptContext` / `declinedDraftSignatures`
（redo.js），以及两处触发点（主编辑器导出成功、历史卷快速导出）。
`POST /api/redo/decline` 因此成了孤儿接口 —— **保留未删**，避免把改动面扩大到后端。

**导出与认领解耦**是这轮最大的收益：老师先印、学生做完，再回来点第四格认领，两个动作不再
绑死在同一个时刻上。四等分后「LaTeX 打包」只剩约 110px，缩为「LaTeX」（全称留在 title）。

### 8.12 切回错题台的落点：把「收口」和「落点」拆开

8.8 修的是「认领跳转」那条路的视图叠加，**同类问题还有一条**：从题库 / 组卷切回错题台。

根因在 `redo.js` 的 `selectWorkspace` 包装层：它只隐掉重做面板，又**无条件**把
`mistakeListView` 打开。而 `openMistakeBatch` 开详情前先关了列表 —— 说明四个顶层视图本就
**互斥**，是这一行打破了不变式。于是「停在切题详情页 → 去题库 → 切回来」会让列表与详情同屏
平分高度，和 8.8 那张截图是同一种病。

修法是把两件事拆开：

- **落点**：重做录入页照旧收起（既有约定：别停在上一轮的录入页），其余**谁开着就落谁**
  （审校 > 详情 > 列表），一个都没开才落回批次列表；
- **收口**：`focusMistakeView(keepId)` 保证只剩落点那一个可见。

新增 `landOnMistakeWorkspace()` 专管这两件事；`closeRedoReview()`（「← 返回批次列表」按钮用）
保持不越权 —— 它只收重做面板本身，别顺手给它加收口。

### 8.13 重做录入页的题面丢图：第五个出口漏了一种语法

用户截图：「组卷台过来的题目图片怎么没有显示？」—— 一道题的题干位置印着
`![插图](/static/uploads/mistakes/1/figures/crop_p015_7eb99e70c0.png)` 这串文字。

**不是图丢了，是渲染器漏了一支。** 库里那道题的正文原文就是 markdown 内联图：

```
如图所示，用频闪照相的方法记录某同学的运动情况，……

![插图](/static/uploads/mistakes/1/figures/crop_p015_7eb99e70c0.png)
```

错题入库时补的图**就是**这么存进去的（`mistake.js` 的补图逻辑写 `'![插图](' + url + ')'`），
写在正文里、未必进 `image_paths`。而 `redo.js` 的 `latexPreviewHtml()` 只认
`\begin{choices}` / `\fillin` / `\paren` 三种结构 —— 漏了 markdown 内联图这一支，于是
`esc()` 之后原样当文字印出来。

同一个出口，五处渲染，只有一处漏：

| 出口 | 位置 | 认 `![]()` | 结果 |
|---|---|---|---|
| 错题详情 / 编辑预览 | `mistake.js` | ✓ | 有图 |
| 组卷台画布 | `paper.js` | ✓ | 有图 |
| 题库编辑器 | `editor.js` | ✓ | 有图 |
| **重做录入页** | **`redo.js`** | **✗** | **一串文字** |
| 导出 PDF | `mathbank/paper_helper.py` | ✓ → `\includegraphics` | 有图 |

最刺眼的是最后一行：**导出的卷子上有图，屏幕上没有** —— 正好破了 `redo.js` 自己写在
`latexPreviewHtml` 上的那条注释（「与 mistake.js 的预览同口径，否则老师会以为导出的卷子
和页面看到的不一样」）。

影响面（全库 1399 题扫一遍）：102 道题命中这种语法（题干或解析），其中 **14 道**
`image_paths` 是空的 —— 图只能靠正文渲染，在重做页 100% 不显示；另外 **68 道**题正文与
`image_paths` 指向同一个文件，它们在重做页「有图 + 多出一串 markdown 文字」。

修法（`redo.js` 一个文件）：

1. 新增 `bodyImagesHtml()`：把 `![alt](url)` 换成 `<img>`，URL 先过 `MathBankSafe.safeImageUrl()`
   （同域 + `/static/uploads/` 前缀 + 位图后缀）；过不了的**原样留着 markdown** ——
   显示一串字顶多难看，静默抹掉会让老师以为这题本来就没配图。题干与解析两处都接上。
2. **去重**：正文里画过的 URL 收进 `inlineFigureUrls`，传给 `figureStripHtml()` 过滤 ——
   不去重那 68 道题会印出两张一模一样的图。去重只掐重复的那张，`image_paths` 里另外的图照常出。
3. **尺寸共用常量** `REDO_FIGURE_CLASS`：正文图与配图数组两条路必须是同一个大小，
   否则同一张图会像两张。

顺带把夹具里的 `MathBankSafe.safeImageUrl` 桩**收紧到与线上同契约**（原来「有值就放行」），
不然「非法 URL 不生成 img」那条分支永远测不出来。

验证：夹具第 14 节 13 项真跑渲染（新断言 7 项对未修复版本会红，已反证）；
真实库副本端到端 `e2e_redo_inline_figure.py` 取真卷（`/api/redo/papers/4`，20 题，其中 14 题
正文带图）喂真 `redo.js`，14/14 通过，生产库零改动。

### 8.15 后续（2026-09-21 全局审查）：图位口径与函数改名

§8.13 里的 `latexPreviewHtml()` / `figureStripHtml()` **已不在 redo.js 里**了。改动来由与
现状记在这里，免得按老名字去找：

- 原状：屏幕上图留在正文出现的原位，试卷 PDF 却把图抽到「题干之后、选项之前」居中
  （`paper_helper.py`：`stem_text → 图 → choices_part`）。录入是照着纸质卷判对错的，
  同一道题两个位置不像同一张卷 → 用户拍板「网页同步」。
- 现在：`questionStemHtml(item)` 先用 `MathRender.inlineFigureUrls()` 扫出正文里的图
  （保持出现顺序），`figureBlockHtml(item)` 把它与 `image_paths` 合并去重成一块，
  通过 `renderQuestionBody` 的 `beforeChoices` 钩子插在**选项之前**。
  正文渲染那一步传 `stripFigures: true`，图不再留在正文流里。
- 公共层新增 `renderQuestionBody` 的 `stripFigures` 选项；同时修掉 `inlineFigureUrls()`
  的一个真 bug（此前复用 `replaceInlineFigures(...).urls`，而那里只在「被替换过」时才
  收集 URL，导致它恒返回空数组）。
- 库里 `figure_align` 有 1398/1399 条是旧默认残留的 `'right'`（`paper_helper.py` 与
  `paper.js:getQuestionFigAlign` 都归一成 `center`，`bottom_right` 为 0），所以配图块
  一律居中，**不做**右侧/居右分支。
- 验证：`tests/js/redo_payload_check.js` 第 14 节改写为 16 项（含「图已抽出」「配图块在
  选项之前」「恰好一个配图块」）；`e2e_redo_inline_figure.py` 增 4 项图位断言，真卷
  20 题（14 题带正文图）**19/19 通过**。
