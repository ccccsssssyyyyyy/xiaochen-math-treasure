## 1. 背景与目标

服务高中生错题改错场景。用户是高中数学教师，同时是高一学生的家长 / 老师，需要把一周的题目扫描件整理成错题本，并逐步沉淀学生的知识掌握档案。

**实际输入形态（用户确认）**

- 主要形态：**一周的题目一次性扫描成多页 PDF**（扫描全能王 App）——本次提供样本为 12 页物理卷
- 也可能：单页；单题
- **导入前，用户已在系统外用专门工具完成「去除手写痕迹」**，交进系统的图片只含印刷体 —— 学生作答、老师红笔批改、荧光笔高亮均已不在图上（见 §7）

**目标**

1. 从扫描件中切出每道题（离线切块，零 token）
2. 标出哪些题做错了（人工点选，**先于识别**）
3. 对选中的错题识别出可编辑题面（VLM 识别为 LaTeX；输入图已是去手写后的干净件）
4. 生成「此次错题本」PDF（含订正留白）
5. 数学错题可一键进题库；物理、化学先不进
6. 远期：按学生沉淀错题档案与知识点掌握情况

## 4. 总体方案

### 4.1 与现有拆卷链路的关系

复用现有能力，只加两道工序。不另起一套上传、OCR、拆题、任务、导出的平行链路。

### 4.2 处理流程（六步）

1. **扫描上传**：一份多页 PDF（或单页 / 单题图）= 一个错题批次。选学科、选学生、填批次标题。
2. **页图转换 + 离线切块（确定性、零 token）**
   - PyMuPDF 按 200–300 DPI 转页图，落 `static/uploads/mistakes/<batch_id>/page_N.png`
   - Pillow 水平投影找行，按「题间距空白」合并成题块，输出每块的纵向范围
   - **切块即为每块建一条 `mistake_records`**（`grad_status = unknown`、`recognize_status = pending`、`content` 留空）
   - 题块图直接落盘为 `image_block`（输入即干净件，无需二次图像处理）
3. **人工点选错题（核心交互，排在识别之前）**
   - 左侧整页图（切块线可视化、可拖动微调、支持手动框选覆盖），右侧题块卡片列表
   - **卡片展示的是题块图缩略图，不是识别后的题面** —— 便于与系统外的原件 / 纸质卷逐题对照
   - ⚠️ **输入图已被去手写，图上不再有任何批改线索**（红笔勾叉、学生错答、荧光笔均已移除）。界面的职责是**承载你的判断结论**，而不是提供线索；判断依据在系统外
   - 每题三态：**对 / 错 / 未批**（默认「未批」，避免漏点即算对的误判）
4. **题块识别（VLM，只跑选中的题）**
   - 触发：点选完成后一键识别本批次全部「错」题；也可对单题单独触发或重试
   - **逐块调用而非整页**：小块图 token 更省、识别更准，且天然得到「每题题面」
   - 提示词要求：只输出题干与选项，不输出解答、不臆造图形（输入图已无手写，**不需要再堆「忽略手写」类反向约束** —— 规则互相打架正是 3I 那次选项被剥离的诱因）
   - 选择题选项走 `\begin{choices}` 归一（复用 `normalize_choice_options_to_latex`）
   - 标记为「对」或「未批」的题**默认不识别**（省 token、省等待）；卡片上留单题识别按钮按需补跑
5. **逐题确认（人工）**
   - 第 4 步的结果以「左题块图 / 右识别题面」并排卡片呈现，题面可 inline 编辑
   - 图形题（几何图、受力图、v-t 图象）在此步从干净件手动截图插入 `image_figure`
   - 两道关卡不能省：VLM 凭印象补全或臆造图形（幻觉）、上游工具可能残留的笔迹
6. **生成错题本 + 入库**
   - 错题本取题依据是 `include_in_handout`（标「错」自动置 true，人工可取消；未批的题也能手动收录）
   - **数学题默认全部入库**（仅限已识别的错题）：批量执行，查重撞车（0.92 相似度）的题**不静默丢弃**，回传清单由你逐题决定「跳过 / 仍入库」

**为什么识别排在点选之后**：一份 12 页卷子约 40–60 个题块，其中错题通常 8–15 题。先点选再识别，VLM 调用量降到约 1/4，等待从几分钟降到几十秒；而判断对错本来就看原图最直观，不需要先有题面文字。

**关于「清除手写」的位置**：**已整体移到系统之外**。用户在扫描后、导入前用专门工具完成去手写，系统收到的是只含印刷体的干净图。因此一期**不含任何图像去笔迹代码**，也不存在「彩色笔迹分离」这类不确定环节。唯一要留意的是去手写工具对图形细线 / 表格的误伤 —— 用户已实测样本图形完好（见 §7、§13）。

### 4.3 判对错的定位

用户已确认**纯人工点选**，且输入图经上游去手写后**不含任何批改痕迹**，因此：

- 系统**不做自动判定，也不做红痕提示**（红笔已不在图上，相关字段与检测整体删除）
- 点选的判断依据来自系统外（原件 / 纸质卷）—— 界面职责是**承载你的结论**，不是提供线索
- 题块卡片提供足够大的缩略图与放大查看，便于与原件逐题对照

**为什么不顺手加「补传原件对照」**：用户明确选择只传干净件，一个批次只保留一份输入。若将来发现对照是高频动作，最小改动是在 `mistake_batches` 增加一个可空 `original_file` 字段 + 详情页一个只读查看器（不改识别链路）—— **一期不做，仅记为扩展点**。

### 5.3 `mistake_records`

**存该批次的全部题目记录**（不只错题）。原因：错题本需要「错题」，而三期学生档案需要正确率，必须知道做对了什么；批次详情页也需要展示完整对错分布。

**粒度差别（2026-09-13 第三轮确认）**

- 每道题都有记录：页号、题块位置、三态标记、切块图 `image_block`
- **但只有被点选为「错」的题识别题面**：`recognize_status = done`、`content` 有值
- 对 / 未批的题：`recognize_status = skipped`、`content` 留空 —— 属于**留档记录**，不能被题库检索、不能被组卷引用，只用于对错分布与三期正确率统计

## 7. 手写与痕迹处理：上游前置（本轮调整核心）

**定位变化**：去手写不再是系统内的一道路径，而是**导入前的上游前置条件**。

**谁做**：用户用专门工具在系统外完成。系统收到的图片只含印刷体 —— 学生黑蓝笔作答、老师红笔勾叉与批注、荧光笔高亮**都已不在图上**（用户 2026-09-13 第二轮确认）。

**系统做什么**：**什么都不做**。

- 不写图像去笔迹代码（原计划的 `mathbank/stroke_clean.py` 与对应单测**整体取消**）
- 不做彩色笔迹分离、不做 AI 图像修复
- 数据模型不保留「清洗前 / 清洗后」两份图，只有一份 `image_block`

**由此得到的三个简化**

1. **VLM 提示词可以精简**：不再需要堆「忽略一切手写内容与批改痕迹」这类反向约束 —— 规则互相打架正是 3I 那次选择题选项被剥离的诱因。提示词只保留「只输出题干与选项、不输出解答、不臆造图形」。
2. **切块步骤由 4 步减为 3 步**：转页图 → 行投影 → 合并题块（原第 4 步「红痕统计」删除）。
3. **图形题截图天然干净**：用户已实测样本的几何图 / 受力图 / v-t 图象在去手写后完好，直接从干净件截取即可，不需要第二套页图。

**边界**：系统不做事后补救。若某次上游去手写效果不佳（残留笔迹、误伤图形细线 / 表格），处理方式是**回上游重做**，而不是在系统里加去笔迹能力。

**依然不做**：AI 图像修复 / 生成式擦除。用户明确不调用大模型绘图，干净件 + 手动截图已足够。

## 13. 风险与边界

| 风险 | 影响 | 应对 |
|---|---|---|
| 上游去手写工具误伤图形细线 / 表格 | 图形题失真 | 用户已实测样本图形完好；若某次误伤，回上游重做（系统不做二次去笔迹） |
| 点选时界面无批改线索 | 离开原件无法判断对错 | 卡片提供大图与放大查看；将来可按需加「补传原件对照」扩展点（一期不做） |

| 切块不准（题跨页、分栏、题间距过小） | 题块错位 | 切块线可视化 + 人工拖动微调 + 手动框选覆盖；分栏卷子列为已知边界 |
| AI 生成的解析本身出错 | 学生被误导 | 解析必须人工核对后才进 PDF；导出页标出未核对项 |
| 解答题（写满推导）切块与识别难 | 题面不准 | 一期接受人工编辑；必要时整题走手动截图 |
| 题库题被改删影响已出错题本 | 数据失真 | 快照字段，导出只读快照 |
| 逐块调用 VLM 的 token 成本 | 费用 | 免费优先路由；逐块小图比整页识别更省 token |
| `main.py` 已 344 KB | 维护性 | 业务逻辑尽量放 `mathbank/`，`main.py` 只做路由与编排（延续现有风格） |

## 14. 成本估算（量级）

- 单题块图（约 1000×600 px）经 VLM token 化约 500–900 tokens；加提示词约 400 tokens
- 一份 12 页卷子按 40–60 个题块计，**全量识别**输入约 50k–80k tokens
- **只识别错题**（通常 8–15 题）→ 输入约 **10k–25k tokens**，约为全量识别的 1/4
- **免费档：0 成本**；付费档（如 qwen3.7-plus / Qwen3-VL-32B）按供应商单价换算，量级在**每份卷子一两角**；若某次确实需要全量识别，上限仍在 1 元量级
- 实际单价以所配置供应商计价为准；`recognize_status = done` 的题不重跑、不重复计费
- **去手写在上游完成，不产生本系统的 API 成本**；系统侧成本仅剩题面识别

### 18.5 沙箱环境的四个坑（与代码无关，仅影响本地验证）

- **`.env` 读取阻塞**：沙箱内 `import main` 会被 `.env` 的 brokered open 卡死（进程被 SIGTERM）。绕过方式是在导入前把 `dotenv.load_dotenv` 打成空实现；真实运行不受影响。
- **复用 keep-alive 连接时第 2 个请求返回 404**：对既有接口（如 `/api/students`）同样如此，带 `Connection: close` 即恢复。属沙箱网络拦截行为，浏览器直连不受影响。
- **`shutil.rmtree` 有「单次批量删除」守卫**：超过 50 个文件会被中断并杀掉进程，`ignore_errors=True` 拦不住（抛的是 `SystemExit`）。验证时先把 `pages` / `blocks` 两个大目录 `mv` 走再调删除接口，即可绕过。**同一守卫也会让单测假失败**：`test_sync.py::test_clean_orphaned_images`（清理孤儿图片）被拦成 `SystemExit: 1`，异常栈指向 `sitecustomize.py` 的 `_check_bulk_delete_guard` —— 这是全量跑里唯一的 failed，看到该路径即可判定为环境问题。
- **pytest 默认 basetemp 会报 `EEXIST`**：沙箱下 `getpass.getuser()` 变成 `root` / `unknown`，默认临时目录 `pytest-of-root` 已存在 → 每个用到临时目录的用例都 `PermissionError`，全量跑出 **173 个 error 全是假故障**（曾据此误判为「测试大面积失败」）。**必须显式加 `--basetemp=/tmp/pytest-base-xxx`**，加上后同样命令得 747 passed / 0 failed。
- **逐文件跑会放大噪声**：用「逐文件 + 单文件 150s 超时」定位卡死点时会看到 `51 ok / 3 失败 / 1 卡死`，但把 3 个失败文件合并重跑是 **32 passed**、卡死的 `test_question_transactions.py` 单独重跑是 **18 passed in 3.11s**。孤立的失败/卡死多属顺序依赖或抖动，**报结论前必须单独重跑**。

## 19. 分栏支持：自动判栏 + 人工纠正（2026-09-14，方案 B 全量落地）

### 19.1 起因

用户上传真实物理卷（16 页）反馈切块异常，并强调「每次上传的文件形式不一定，可能分左右排版，也可能拉通下来」。原切块是**整页宽水平行投影**，`BlockRegion` 只有 y 范围 —— 双栏卷左右栏纵向错开，空白处总有字，切点消失（实测 p2 全宽投影只切 6 块，其中一块高 1224 px、占页面 52%，把左栏「三、简答题 + 第 11 题」与右栏「第 12 题」压进同一块）；即便切出边界，`crop_region` 按全宽裁也会把两栏半道题拼在一起。

### 19.2 判据（两次弯路后的定型）

**第一次实现失败**：用「逐行是否被切成两段」判栏，导致 p9–p13（通栏页，选项 A/B/C/D 横排）全部误判为双栏 —— 每行本来就有多段，该判据对通栏页根本失灵。

**定型判据：横向覆盖率剖面 + 中缝**。整页二值图 BOX 重采样到 200×400，统计「有墨的纵向带里有多少带在这一列也有墨」，则

| 条件 | 阈值 | 实测两档 |
|---|---|---|
| 中缝覆盖率 | ≤ 0.05 | 双栏 0.000–0.016 / 单栏 0.038–0.286（4 倍余量） |
| 缝两侧覆盖率 | ≥ 0.12 | 双栏 0.220–0.312 / 半页内容页 0.021–0.106 |
| 缝两侧各有一段成栏内容 | ≥ 0.25 页宽 | 真栏每行一整段 0.33–0.44 / 分段页每段 0.12 |

第三条是区分「双栏」与「通栏但每行多段（选项横排 / 表格行）」的关键：这类页必然有一个段间隙落进中缝扫描窗，前两条都能满足。

**两个必须记住的实现点**（已钉进代码注释）：

1. 文本层必须取 `get_text("dict")` 的 **lines 而非 blocks** —— 块会把左右栏合并成一个通栏块（如 `[0.02, 0.92]`），行级才是若干独立窄行。这是 p9–p13 误判的直接根因。
2. 剖面「有墨」判定必须用 **`> cutoff`**（墨迹 = 255，与 `_ink_profile` 同一约定）。写成 `<` 会让整页每格都算有墨、中缝消失、**16 页全判单栏**。

### 19.3 分层改动

| 层 | 内容 |
|---|---|
| 算法 | `BlockRegion` 升级 2D（`x_start`/`x_end`/`column_index`）；`ColumnLayout` + `manual_column_layout`；两条判栏路径（文本层 / 图像）共用剖面判据；`recut_blocks_by_column` 按栏重切（栏号 1/2 为该栏完整切点集、空列表＝整栏并一块、0＝横跨两栏补一刀）；块编号重排 0..n-1 |
| 数据 | `MistakeRecord` 增 `block_x_start`/`block_x_end`/`column_index` + `v1006` 迁移 |

### 19.4 交互上的三个决定

1. **改栏目不立刻重切**：拖动要跟手，中途反复重切又慢又看不清；改为提示「待重切」+ 一键按钮。
2. **拖完吞掉紧随的 click**：pointerup 之后浏览器会补一个 click，不吞就会在补线模式下顺手多插一条切线（`layoutDragUntil`）。
3. **人工栏目随每一次重切提交**：重切是「整批重算、只替换被点名的页」，不带上就等于把用户改过的页悄悄退回自动判栏。切线同理，只带被点名的那页。
