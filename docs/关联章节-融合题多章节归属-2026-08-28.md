# 关联章节 / 融合题多章节归属

> 日期：2026-08-28
> 模块：题库工作台（录入 / 导入 / 分类）
> 状态：功能完成，单测 + E2E + jsdom 回归全部通过

## 一、背景与目标

实际教学中很多题目是**融合题**（一道题横跨多个章节，例如"集合与不等式""函数与导数"同时涉及）。
原先每道题只能归属到**一个主章节**（`category_chapter`），导致：

- 融合题在"按章节筛选"时只能出现在主章节下，关联章节里搜不到；
- AI 自动分类也只能回填一个章节，丢失了题目真正的跨章节属性。

本次改动让每道题支持**关联章节（可多选）**，并在章节筛选、AI 分类、前端录入/导入全链路打通。

## 二、后端改动

### 1. 数据模型 `mathbank/database.py`
- `Question` 新增 JSON 文本列：`related_curriculums = Column(Text, default="[]")`。
- 新增 `_safe_json_list()` 解析辅助，保证脏数据不炸。
- `to_dict()` / `to_summary_dict()` 输出该字段。
- `init_db()` 中对存量库做**幂等 ALTER**（列已存在则跳过）。

### 2. 归一化 `main.py::parse_related_curriculums(raw)`
把各种输入统一成 `[{compulsory, chapter, knowledge}, ...]` 的 JSON 字符串：
- 空串 / 空白 / `None` / 非列表 → `"[]"`；
- 列表直接透传，字符串 JSON 解析；
- **丢弃没有章节（`chapter` 为空）的条目**；
- 按 `(compulsory, chapter, knowledge)` **去重**；
- 忽略非 dict / 非法元素。
- 作为 `create_question` / `update_question` 的 Form 参数接入。

### 3. 章节筛选（关键修复）`main.py::list_questions` 与 `ai_select_paper`
原筛选用脆弱的 `LIKE '%"chapter": "..."%'`，有两个 bug：
- 缺前导 `%`，永远匹配不到以 `[{` 开头的 JSON；
- `ESCAPE '\'` 子句反而破坏了匹配。

改为使用 **SQLite JSON1** 的 `json_each` + `json_extract` 精确匹配：

```python
if chap_val:
    query = query.filter(
        or_(
            Question.category_chapter == chap_val,
            text("EXISTS (SELECT 1 FROM json_each(questions.related_curriculums) "
                 "WHERE json_extract(value, '$.chapter') = :chap)"),
        )
    ).params(chap=chap_val)
```

效果：一道题只要**主章节**或**任一关联章节**命中，就会出现在该章节下（融合题在它涉及的所有章节都可见）。

### 4. AI 分类 `mathbank/prompts.py` + 分类接口
- 系统提示新增第 9 条规则：输出 `related_chapters`（数组，结构同 `related_curriculums`）。
- 分类接口接收并写入 `related_chapters` → 回填到录入表单。

## 三、前端改动

### `static/index.html` + `static/js/editor.js`
- 录入表单新增「关联章节（融合题适用，可多选）」分区：
  - 学段 / 章节 / 小节 **三级联动**下拉（与主分类同源 `categoryTree`）；
  - 「添加关联章节」按钮 → 渲染为 `relatedChaptersChips` 标签；
  - 自定义标签区加 **10 个预设思维方法标签**（数形结合、转化与化归、函数与方程、分类讨论、特殊与一般、正难则反、构造法、极限思想、向量法、坐标法）。
- 草稿卡 / 题库卡在有关联章节时显示 **`+N关联`** 角标。
- `populateCategoryDropdowns()` 现在同时填充关联章节下拉。

### `static/js/import.js`
- 全局 `window.relatedChapters` 及 `setRelatedChapters` / `getRelatedChapters` / `renderRelatedChaptersChips` / `addRelatedChapterFromSelects` / `setupPresetTopicTags`。
- `saveQuestion`、题目载入（`useQuestion`）、新增/重置流程都接入 `related_curriculums`。
- `applyClassifyResultToEditor` 在 AI 回填时同步写入关联章节。

## 五、本次修复的一个隐蔽 Bug（复盘）

`import.js` 中 `applyClassifyResultToEditor` 的"关联章节回填"代码块被误放在**函数闭合 `}` 之后**（即 IIFE 顶层），
而代码块引用了函数参数 `data` → 加载时抛 `ReferenceError: data is not defined`，
导致整个 IIFE 在到达初始化入口前就中止，`startImportParseClick` 永远未定义，`multifile_test.js` 失败。

修复：把该代码块（含 `window.applyClassifyResultToEditor = ...` 赋值）移回函数体内。
同时移除了调试期的 `initApp` 重构与所有 `[INIT-DBG]` / `window.__*` 探针，恢复为原始的
`document.addEventListener('DOMContentLoaded', () => { ... })` 初始化方式。

## 六、使用方式（对用户）

1. 在录入 / 导入表单找到「关联章节（融合题适用，可多选）」；
2. 选 学段 → 章节 → 小节，点「添加关联章节」，可加多个；
3. AI 自动分类后会自动带上关联章节，可手动增删；
4. 在左侧章节树点任意章节，融合题会出现在它主章节**和**所有关联章节下。
